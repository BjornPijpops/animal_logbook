# ADR 0002: Authentication with Better Auth

Status: Accepted (deviation point: the brief allowed Auth.js or Better Auth)

## Context

Need self-hosted email+password and optional OAuth, no hosted provider. Auth.js (NextAuth) v5 has remained in beta, its credentials provider is deliberately minimal (no built-in password reset, verification, rate limiting), and the project now lives under the Better Auth organisation.

## Decision

Use **Better Auth** with the Drizzle adapter: email+password, email verification and reset via the `NotificationChannel`/mailer, optional OAuth providers enabled only when env client ids are set (e.g. GitHub, Google OAuth apps are free). Database sessions in Postgres, HttpOnly SameSite=Lax secure cookies, Argon2id/scrypt hashing (library default or `@node-rs/argon2`).

## Consequences

- Users/sessions/accounts tables are generated by Better Auth; our `users` extras (locale, timezone, units) are added via its additional-fields API.
- Sign-up hook creates the user's household and owner membership in one transaction.
- Auth endpoints are rate limited by our Postgres limiter.
- Fallback: Auth.js with a custom credentials flow if Better Auth blocks us; recorded as a new ADR.
